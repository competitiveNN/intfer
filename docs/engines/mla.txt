https://github.com/sootaugur/qwen-mla-vllm # MLA/GA survey (2026-10-16): vLLM plugin with MLA (TP=1) and GLA-g2 (TP=2). Upstream Triton kernels CANNOT be ported (Triton not SYCL/Xe, model-type conversion required). intfer implements its OWN MLA/GA path behind INTFER_MLA_ATTN (see sabicap entry above for the implementation record). DECLINED as a port, ADOPTED as an informed-from-scratch opt-in feature.
CAPABILITY GAP RECORDED 2026-10-18 (the verdict on reminder 7, so it is not re-derived later as "not yet attempted") -- intfer's MLA path is a PURE ARITHMETIC RE-ROUTING and realises NONE of MLA's KV-cache memory win: it compresses Q/K/V into a latent, decompresses them, and writes the DECOMPRESSED rows into ly.kcache/ly.vcache before falling through to the existing grouped-attention pass, exactly as its own comment states at examples/intfer_cli/main.cpp:5525-5526. Upstream's three genuinely transferable capabilities, none of them ported: (i) a LATENT-RESIDENT KV CACHE -- upstream caches a per-layer latent plus a small RoPE and normalisation tail instead of per-head keys and values, which is the memory win intfer lacks; (ii) GLA-g2 AT TP=2 -- upstream splits the latent into two head groups so per-GPU KV halves under tensor parallelism, where plain MLA replicates its latent on every rank; (iii) a per-head score divisor kept as a ONE-BYTE LOG2 CODE (0.8% max error where e4m3 gives 6%). WHY THE LATENT-RESIDENT KV CACHE IS DECLINED RATHER THAN IMPLEMENTED BEHIND A DEFAULT-OFF FLAG, and the reason is this repo's own precedent: the flag requires cfg.kv_lora_rank > 0 AND the q_a/q_b/kv_a/kv_b tensors, so on the shipped 27B GQA weights it is inert by construction -- a latent-resident cache would therefore be DEAD CODE AT THE 27B --tp 2 TARGET, which is the "default-OFF flag no gate can reach" class and the same reason Engine::run_mlp_fused and Engine::run_linear_tp_devact are recorded as TP=1-locked. There is also no MLA fixture model in this tree, so a gate arm could assert source structure only and could not be non-vacuous in the sense the existing INTFER_MLA_ATTN arm already is. And on the standing fusion test it removes no device round trip at the target while rewriting the attention score/output pass to decompress on the fly. sootaugur/qwen-mla-vllm itself is blocked twice over: it is a vLLM 0.27.1-ONLY plugin and it is NVIDIA-ONLY (its README reports RTX PRO 6000 Blackwell and RTX 5060 Ti, H100 earlier), with Triton decode kernels and a patched FlashInfer CUDA build, so no kernel transfers and the dependency cannot be satisfied by this tree.
