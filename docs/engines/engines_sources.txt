# THE DECISIVE GENERAL FACTS, all three applying:
# (a) The DashQ INT2 weight-format wall applies: intfer's weights are packed INT2
#     codes + per-(row, K-group) FP16 scales + a host global divisor, so porting a
#     foreign weight-layout kernel is a re-quantisation of the whole 27B, not a
#     micro-optimisation.
# (b) No-P2P applies: intfer has no P2P/IPC transport, so no cross-device
#     collective has a consumer.
# (c) This engine's KV design is the OPPOSITE of what intfer optimises for: its
#     whole transfer-reduction apparatus (pinned staging pool, async page DMA, page
#     reuse) exists because its KV lives on the DEVICE and pages must move, whereas
#     intfer's objective is to get intermediates off the host and keep work
#     device-resident. Those ideas point the wrong way for this tree.

# seam, nor the memory objective this tree optimises for; and its one genuine
# capability gap (eviction policy) is already solved here by a different mechanism
# (snapshot/resume prefix cache). Longer record: docs/engines/pulsarlm.txt

# MODEL-LEVEL KNOWLEDGE (confirmed against source; no code to port):
# - Layer-kind structure: `full_attention_interval` decides full-attention versus
#   GatedDeltaNet by position, and the two kinds carry DISJOINT weight sets --
#   attn_q/k/v/output(+q_norm/k_norm) for a full layer, attn_qkv/gate/ssm_a/
#   ssm_conv1d/ssm_dt/ssm_alpha/ssm_beta/ssm_norm/ssm_out for a GDN one
#   (src/models/qwen/weights.cpp:190-244), with the per-layer expectation asserted at
#   upstream/src/models/qwen/weights.cpp:250-260 ("Unexpected Qwen layer kind at blk.N"). This CONFIRMS
#   intfer's `ly.is_full` dispatch is already correct: intfer/examples/intfer_cli/main.cpp:6339/6349 (the
#   full-attn branch closes and the GDN branch opens in prefill_layer_outer) and
#   intfer/examples/intfer_cli/main.cpp:11639 (the spec restore's per-kind state rebuild). No change warranted.
# - GDN state is TINY, so the SSM is launch/transfer-bound, not bandwidth-bound:
#   recurrent = ssm_num_v_heads * ssm_head_dim * ssm_head_dim and
#   conv = (ssm_conv_kernel - 1) * SsmConvChannels()
#   (src/models/qwen38_flash_next/kernels/rocm/executor.cpp:807-809), tabulated for
#   the retained model as "GDN recurrent matrix | private f32, per linear layer |
#   3,145,728/layer" (docs/models/qwen3.8-flash-next/CONTINUATION-ADAPTER.md:22)
#   against 24,576 bytes per target token of attention K/V on the same table (:18).
#   This independently corroborates intfer's INTFER_SSM_FUSE decision: at ~3 MB per
#   layer class the recurrence's cost is submits and transfers, which is exactly
#   what the 2-pass fold buys, so the decision rests on nk/nw/nr.
# - gufo's own rejected byte-exact micro-optimisations corroborate the PARAMOUNT
#   DIRECTIVE from the other side: "Sixteen-row Q5 row-first FMA operand schedules"
#   and "Compact sixteen-row Q5 staging and register activation sums"
#   (docs/models/qwen3.8-27b/EXPERIMENTS.md:54,59), "Non-temporal paired
#   expert-code loads" (docs/models/qwen3.8-flash-next/EXPERIMENTS.md:102) -- all
#   byte-exact but slower -- while it RETAINS the launch-count ones ("Skip unused
#   SSM activation copies and routed-row clears | Retained: 96 fewer launches per
#   pp2048", docs/models/qwen3.8-flash-next/EXPERIMENTS.md:9). Fusion and launch
#   reduction, not arithmetic, is the direction in both trees.
# - COMPILER-ARTEFACT LESSON, carried as a standing rule: a regression that was NOT
#   a code change but a compiler's register allocation was caught by measuring
#   emitted resources, not tok/s. gufo's "Clang 23 prefill GEMM spills | Retained: a
#   `sched_barrier` fence per K block in BK=2 W8A8 tiles, no K-block unroll in BK=4
#   tiles, SLP off for the two K-quant units. Clang 23 (ROCm 10.0) Q8 pp2048 291 ->
#   464, pp64 112 -> 308, Q4 pp64 230 -> 335 ... Greedy output and prefill
#   validation are byte-identical. Clang 22: pp2048 and decode do not change, 16-64
#   token prefill is 1.2-1.7% slower." (docs/models/qwen3.8-27b/EXPERIMENTS.md:103),
#   with the same family appearing as "clang 23's address-selected private cache
#   (80 B, 0 spills)" in the flash-next table (:95). A byte-identical-output
#   slowdown with a compiler-version boundary is a BUILD ARTEFACT, not a code
#   fault, and the instrument that sees it is a resource counter -- the
#   load-insensitive class this repo's own counters belong to.
