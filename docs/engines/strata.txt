Upstream's typed remedy waits_ms polls an EVENT -- a QUERY, not a blocking sync, 0.021 ms -- and intfer's own seams already hold that shape: every GEMM readback in src/engine/engine.cpp is gated behind a get_profiling_info<command_start/command_end> query, sixteen of them, so there is no doorbell to add to a readback that already forces the driver to report. THE RELEASE-BEFORE-DRAIN AUDIT ASKED FOR BY THE SAME ITEM DID RUN, AND IT FOUND A REAL GAP, WHICH IS NOW FIXED: the two growth paths already drain (ensure_wave_workspace and ensure_workspace each call devices_[d].queue.wait() before freeing the replaced .out buffer), but Engine::~Engine did not. A pointer allocated through the Level Zero path is released with zeMemFree, and zeMemFree UNMAPS it, so an Engine torn down with work in flight could unmap a buffer the device was still writing -- the xe fault Strata records on this driver family. The destructor now scans ws_[d].out_uncached / wv_[i].out_uncached and, only if one of them is set, drains every device queue before the workspace frees; the drain is CONDITIONAL, so the shipped (flag-unset) path is unchanged in behaviour and cost and the drain is reachable only under the flag.
